# \# AuthenticRAG: การเปรียบเทียบระบบ Retrieval-Augmented Generation

# 

# โปรเจกต์นี้พัฒนาเพื่อศึกษาและเปรียบเทียบประสิทธิภาพของวิธีการค้นคืนข้อมูล (Information Retrieval) สำหรับระบบ Retrieval-Augmented Generation (RAG) โดยเปรียบเทียบระบบพื้นฐาน (\*\*Baseline\*\*) กับระบบที่ปรับปรุง (\*\*Improved\*\*) ซึ่งเพิ่มการใช้กราฟความสัมพันธ์ของข้อมูลเพื่อช่วยค้นคืนเอกสารที่เกี่ยวข้อง

# 

# \## 1. วัตถุประสงค์ของโปรเจกต์

# 

# \- พัฒนาระบบ Baseline สำหรับค้นคืนเอกสารที่เกี่ยวข้องกับคำถาม

# \- พัฒนาระบบ Improved ที่นำ Graph Expansion มาใช้เพื่อขยายการค้นคืนจากข้อมูลที่มีความสัมพันธ์กัน

# \- เปรียบเทียบกระบวนการค้นคืนข้อมูลของทั้งสองระบบ

# \- ประเมินผลการค้นคืนด้วยตัวชี้วัดที่เหมาะสม เช่น Recall@K, Precision@K, MRR และ NDCG@K

#

# \## 3. แนวคิดและกระบวนการทำงาน

# 

# \### 3.1 Baseline: ระบบค้นคืนข้อมูลพื้นฐาน

# 

# Baseline ใช้เป็นระบบอ้างอิงสำหรับเปรียบเทียบกับระบบที่ปรับปรุง โดยมีกระบวนการค้นคืนข้อมูลตามที่กำหนดไว้ในโค้ด

# 

# องค์ประกอบหลักของแนวทางที่ใช้ ได้แก่

# 

# \- \*\*BM25:\*\* ใช้ค้นคืนเอกสารจากความเกี่ยวข้องของคำในข้อความ

# \- \*\*BGE-M3:\*\* ใช้สำหรับสร้าง Embedding เพื่อค้นคืนข้อมูลเชิงความหมาย

# \- \*\*Reciprocal Rank Fusion (RRF):\*\* ใช้รวมอันดับผลการค้นคืนจากหลายแหล่ง

# \- \*\*Top-K Retrieval:\*\* เลือกเอกสารจำนวน K รายการแรกตามอันดับที่ได้

# 

# กระบวนการโดยสรุป:

# 

# 1\. รับคำถามจากผู้ใช้

# 2\. ค้นคืนเอกสารด้วยวิธีที่ระบบกำหนด

# 3\. รวมอันดับผลการค้นคืนด้วย RRF

# 4\. เลือกเอกสาร Top-K เพื่อใช้เป็นผลลัพธ์

# 

# \### 3.2 Improved: ระบบค้นคืนข้อมูลที่ใช้กราฟช่วยขยายผล

# 

# ระบบ Improved เพิ่มการใช้กราฟความสัมพันธ์ของข้อมูลเพื่อช่วยค้นคืนเอกสารที่อาจเกี่ยวข้องกับเอกสารตั้งต้น

# 

# องค์ประกอบที่ศึกษา ได้แก่

# 

# \- \*\*Hybrid Retrieval:\*\* ใช้ผลการค้นคืนจากหลายวิธีร่วมกัน

# \- \*\*Graph Seed Identification:\*\* ระบุข้อมูลตั้งต้นบนกราฟจากผลการค้นคืน

# \- \*\*Graph Expansion:\*\* ขยายการค้นคืนไปยังโหนดที่มีความสัมพันธ์กับข้อมูลตั้งต้น

# \- \*\*Candidate Merging:\*\* รวมรายการเอกสารจากการค้นคืนและการขยายกราฟ

# \- \*\*Cross-Encoder Reranking:\*\* จัดอันดับเอกสารผู้สมัครใหม่ตามความเกี่ยวข้องกับคำถาม

# \- \*\*Context Construction:\*\* เตรียมเอกสารที่ผ่านการคัดเลือกเพื่อใช้เป็นบริบท

# 

# กระบวนการโดยสรุป:

# 

# 1\. รับคำถามจากผู้ใช้

# 2\. ค้นคืนเอกสารเพื่อสร้างรายการเอกสารผู้สมัคร

# 3\. ระบุข้อมูลตั้งต้นและขยายการค้นคืนผ่านกราฟ

# 4\. รวมรายการเอกสารจากแหล่งต่าง ๆ

# 5\. จัดอันดับเอกสารใหม่ตามกระบวนการที่กำหนดในโค้ด

# 6\. เลือกเอกสารสำหรับสร้างบริบท

# 

# > หมายเหตุ: รายละเอียดของแต่ละขั้นตอนขึ้นอยู่กับการทำงานจริงของไฟล์ในโฟลเดอร์ `improved/` ควรตรวจสอบโค้ดก่อนใช้คำอธิบายนี้เป็นข้อสรุปเชิงเทคนิคของงานวิจัย

# 

# \## 4. การเปรียบเทียบระบบ

# 

# | ประเด็น | Baseline | Improved |

# |---|---|---|

# | แนวทางหลัก | การค้นคืนเอกสาร | การค้นคืนร่วมกับกราฟความสัมพันธ์ |

# | การค้นคืนข้อมูล | ตามวิธีที่กำหนดในระบบพื้นฐาน | ค้นคืนและขยายผลผ่านกราฟ |

# | การใช้กราฟ | ไม่ใช่องค์ประกอบหลักของระบบ | ใช้กราฟเพื่อช่วยค้นคืนข้อมูลที่สัมพันธ์กัน |

# | การจัดอันดับ | ใช้กระบวนการจัดอันดับของ Baseline | เพิ่มการจัดอันดับใหม่ หากเปิดใช้งานในโค้ด |

# | การประเมินผล | ใช้ชุดคำถามและเกณฑ์เดียวกัน | ใช้ชุดคำถามและเกณฑ์เดียวกัน |

# ตารางนี้อธิบายความแตกต่างเชิงแนวคิดของทั้งสองระบบ ไม่ใช่ผลการทดลองที่ยืนยันว่าระบบใดดีกว่า

# \## 5. เทคโนโลยีที่เกี่ยวข้อง

# 

# \- Python สำหรับพัฒนาระบบ

# \## 8. แนวทางการประเมินผล

# 

# เพื่อให้เปรียบเทียบ Baseline และ Improved ได้อย่างเป็นธรรม ควรใช้ชุดคำถาม ชุดเอกสาร และเกณฑ์การประเมินเดียวกัน

# 

# ตัวชี้วัดที่สามารถใช้ได้ ได้แก่

# 

# | ตัวชี้วัด | ความหมาย |

# |---|---|

# | Recall@K | สัดส่วนเอกสารที่เกี่ยวข้องซึ่งระบบค้นคืนได้ภายใน K อันดับแรก |

# | Precision@K | สัดส่วนเอกสารที่เกี่ยวข้องในผลการค้นคืน K อันดับแรก |

# | MRR (Mean Reciprocal Rank) | วัดอันดับของเอกสารที่เกี่ยวข้องรายการแรกโดยเฉลี่ย |

# | NDCG@K | วัดคุณภาพการจัดอันดับ โดยคำนึงถึงความเกี่ยวข้องและตำแหน่งของเอกสาร |

# 

# ควรจัดเตรียมชุดคำถามพร้อมรายการเอกสารที่เกี่ยวข้องจริง (Ground Truth) เพื่อใช้คำนวณตัวชี้วัด และรายงานผลของแต่ละระบบด้วยเงื่อนไขการทดลองเดียวกัน

# 

# \## 9. ข้อจำกัดและข้อควรพิจารณา

# 

# \- คุณภาพของผลการค้นคืนขึ้นอยู่กับคุณภาพและความครอบคลุมของเอกสารต้นทาง

# \- Graph Expansion อาจช่วยค้นคืนข้อมูลที่เชื่อมโยงกัน แต่ก็อาจเพิ่มเอกสารที่ไม่เกี่ยวข้องได้

# \- Cross-Encoder Reranking อาจเพิ่มเวลาในการประมวลผล

# \- ผลลัพธ์ขึ้นอยู่กับโมเดล พารามิเตอร์ และการตั้งค่าของระบบ

# \- ควรประเมินผลด้วยข้อมูลจริงก่อนสรุปว่าระบบ Improved มีประสิทธิภาพเหนือกว่า Baseline

# 

# \## 10. สรุป

# 

# โปรเจกต์ AuthenticRAG มุ่งศึกษาการปรับปรุงกระบวนการค้นคืนข้อมูลสำหรับระบบ RAG โดยเปรียบเทียบระบบพื้นฐานกับระบบที่ใช้กราฟความสัมพันธ์ช่วยขยายผลการค้นคืน การทดลองและการประเมินผลจะช่วยให้เห็นข้อดี ข้อจำกัด และความเหมาะสมของแต่ละแนวทางภายใต้เงื่อนไขที่กำหนด
